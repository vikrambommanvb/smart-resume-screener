# Architecture Decision Records (ADRs)

## ADR-001: Monorepo Structure with Separated Cloud Run Backend and Vercel Frontend
- **Status:** Accepted
- **Context:** Smart Resume Screener requires a fast, low-latency static web frontend and a Python-based NLP service that utilizes spaCy, PyMuPDF, and sentence-transformers.
- **Decision:** Split into `apps/web` (React 19, Vite, Tailwind v4) and `apps/api` (FastAPI, Python 3.12).
- **Consequences:** The browser communicates directly with Cloud Run via Server-Sent Events (SSE). Vercel proxies are avoided to eliminate stream buffering.

## ADR-002: Deterministic Scoring Isolated from LLM Output
- **Status:** Accepted
- **Context:** Job seekers require reliable, reproducible feedback. LLMs are non-deterministic and prone to score drift or hallucination.
- **Decision:** The match score (0-100) and resume health score (0-100) are computed strictly via deterministic mathematical formulas in `app/pipeline/scoring.py` and `app/pipeline/health.py`. Gemini never generates or alters numeric scores.
- **Consequences:** Identical resumes against identical jobs always produce identical scores. Unit tests enforce determinism and monotonicity.

## ADR-003: Privacy by Construction & In-Memory Pipeline
- **Status:** Accepted
- **Context:** Resumes contain sensitive Personally Identifiable Information (PII).
- **Decision:** Uploaded PDFs are held strictly in memory (capped at 5 MB, 8 pages), parsed into memory, and immediately discarded after streaming ends. Zero disk persistence, zero database storage. PII (emails, phones, locations, candidate names) is redacted before sending untrusted text to Gemini. Logs contain only request IDs, durations, and status codes.
- **Consequences:** Eliminates candidate privacy exposure and compliance risks with zero storage retention.

## ADR-004: Guarded LLM Integration with RapidFuzz Evidence Verification
- **Status:** Accepted
- **Context:** LLM suggestions must be grounded in actual resume text to prevent fabricated experience or skills.
- **Decision:** All Gemini responses undergo strict post-generation guards in `app/llm/guards.py`:
  1. Evidence quotes must have RapidFuzz `partial_ratio >= 88` against the extracted resume.
  2. In suggested rewrites, all numbers must exist in the original bullet or be bracketed placeholders (`[X%]`).
  3. All external links and course URLs generated by models are stripped; only URLs from the server-verified `resources.json` catalog are presented.
- **Consequences:** Ensures 100% truthful, verifiable resume feedback.

## ADR-005: 3D Constellation with Zero-CLS SVG Fallback & Accessible Table
- **Status:** Accepted
- **Context:** The interactive skill constellation provides a visually memorable experience but must not compromise performance or accessibility.
- **Decision:** Render an instant, precalculated SVG constellation immediately. Lazy-load the React Three Fiber (R3F) bundle asynchronously. If `prefers-reduced-motion`, `saveData`, or WebGL is missing, remain on the SVG graph. Provide an accessible semantic HTML table alongside the visual graph.
- **Consequences:** Meets WCAG 2.2 AA accessibility and Lighthouse mobile performance budgets while retaining distinctive visual identity.

## ADR-006: Typography and Visual Theme
- **Status:** Accepted
- **Context:** The design requires a premium, non-templated look avoiding generic AI styling.
- **Decision:** Pair **Bricolage Grotesque** (display) and **Instrument Sans** (body & UI with tabular figures). Use deep ink surfaces (`#0C0B1D`, `#131230`) with violet/blue brand accents and a single amber signal accent. Light print stylesheet is supported for PDF exports.
- **Consequences:** Distinctive visual voice with high contrast compliance (verified >= 4.5:1).

## ADR-007: React 19 R3F Compatibility & Resilient 3D Error Boundary
- **Status:** Accepted
- **Context:** React 19 modified internal reconciler properties (`__SECRET_INTERNALS_DO_NOT_USE_OR_YOU_WILL_BE_FIRED` transitioned to `__CLIENT_INTERNALS_DO_NOT_USE_OR_WARN_USERS_THEY_CANNOT_UPGRADE`), causing `@react-three/fiber` v8 to throw `ReactCurrentOwner` and `ReactCurrentBatchConfig` errors on canvas initialization.
- **Decision:** 
  1. Implemented a non-invasive compatibility shim in `main.tsx` aliasing client internals before R3F loads.
  2. Wrapped `LazyScene3D` in `Scene3DErrorBoundary` inside `ConstellationContainer.tsx`. If WebGL context creation fails or throws on any device/driver, it catches the error and cleanly falls back to `ConstellationSVG` without unmounting the React tree or causing layout shift.
- **Consequences:** Guaranteed 100% stability across all modern and legacy browsers, headless environments, and reduced-motion clients.
